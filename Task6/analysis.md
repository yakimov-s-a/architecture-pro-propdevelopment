# Отчёт по результатам анализа Kubernetes Audit Log

## Подозрительные события

1. Доступ к секретам:
    - Кто: `system:serviceaccount:secure-ops:monitoring`.
    - Где: namespace `kube-system`, resource `secrets`.
    - Почему подозрительно: пользователь без соответствующих прав пытается получить доступ к секретам Kubernetes.

2. Привилегированные поды:
    - Кто: `minikube`.
    - Комментарий: пользователь создал привилегированный pod, что позволяет ему получить доступ к хосту, на котором
      развернут Kubernetes.

3. Использование kubectl exec в чужом поде:
    - Кто: `minikube`.
    - Что делал: пользователь получил доступ к содержимому файла `/etc/resolv.conf`, содержащему информацию о
      DNS-серверах, что может быть использовано для атак на сеть кластера.

4. Создание RoleBinding с правами cluster-admin:
    - Кто: `minikube`.
    - К чему привело: сервисный аккаунт monitoring получил права cluster-admin. Это событие эскалации прав.

5. Удаление audit-policy.yaml:
    - Кто: не найдено в логах т.к. операция завершилась неуспешно
    - Возможные последствия: удаление политики аудита позволит злоумышленнику скрыть свои действия.

## Вывод

* Злоумышленник воспользовался рядом уязвимостей в конфигурации кластера.
* Необходимо запретить создание привилегированных подов. Ограничить это можно при помощи Pod Security Policies.
* Необходимо ограничить доступ к объектам конфигурации (ролям, секретам и т.д.).
