# Требования к безопасности

## Требования

* Контроль трафика: все взаимодействие с внешней системой должно происходить через firewall.
* Шифрование: все данные должны быть зашифрованы во время передачи и хранения.
* Изоляция: доступ к данным системы PropDevelopment со стороны сторонней системы должен осуществляться только через
  специализированный API. Прямой доступ к данным системы исключен.
* Принцип минимальных привилегий: сторонняя система должна иметь доступ только к тем данным, которые необходимы для
  выполнения текущей операции.
* Персональные данные: передача биометрии и других персональных данных пользователей системы наружу исключена.
    * Сторонняя система должна передавать зашифрованные биометрические шаблоны для проверки внутренней системой.
    * Для автомобильных номеров может быть реализована передача в систему не оригинального значения, а хеша.
* Токенизация: персональные данные должны быть токенизированы для минимизации передачи их напрямую между различными
  системами.
* Ротация токенов: токены доступа, используемые для взаимодействия с внешней системой, должны регулярно обновляться.
* Логирование: все обращения внешней системы должны логироваться.
* Мониторинг: должен быть реализован мониторинг и реагирование на подозрительные события во взаимодействии с внешней
  системой.

## Протоколы

* HTTPS + TLS 1.3 — для шифрования данных во время передачи.
* OAuth 2.0 с Client Credentials — для аутентификации при взаимодействии между серверами систем.
* WebRTC + STUN / TURN — для трансляции видео из домофона в приложение клиента.

## Взаимодействие с внешней платформой

### Открытие двери по звонку

1. Происходит вызов через видеодомофон в квартиру.
2. Внешняя система через API сообщает о том, что происходит звонок. Передает токен, который соответствует вызываемому
   объекту недвижимости, а также передается зашифрованный шаблон биометрии вызывающего.
3. Внутренний сервис проверяет наличие соответствующего объекта недвижимости в базе данных по токену.
4. Для объекта недвижимости находится привязанный пользователь, и происходит сверка шаблонов биометрии.
5. Если шаблоны совпадают, то переходим к открытию двери. Если шаблоны не совпадают, то пользователю отправляется
   уведомление о вызове, и он может подтвердить открытие двери вручную.
6. Внутренняя система вызывает API внешней системы для открытия двери и передает токен объекта.
7. Внешняя система отдает команду на открытие двери домофону.

### Открытие шлагбаума

1. Камера шлагбаума фиксирует номер подъехавшей автомобиля.
2. Внешняя система через API сообщает о том, что нужно проверить номер автомобиля. Передает токен, который соответствует
   объекту недвижимости, а также передается хешированный номер автомобиля.
3. Внутренний сервис проверяет наличие соответствующего объекта недвижимости в базе данных по токену.
4. Для объекта недвижимости находится привязанный пользователь, и происходит сверка хеша номера автомобиля с номерами
   пользователя.
5. Если хеш совпадает, то внутренняя система вызывает API внешней системы для открытия шлагбаума и передает токен
   объекта.
6. Внешняя система отдает команду на открытие шлагбаума.

Ключевым в данных процессах является то, что персональные данные (биометрия, номера автомобилей, адреса объектов
недвижимости) не передаются в явном виде между внешней и внутренней системами.

Передаются токены, которые имеют ценность только в привязке к другим данным в БД.
